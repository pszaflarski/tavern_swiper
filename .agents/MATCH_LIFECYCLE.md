# 🏰 Architectural Deep Dive: Multi-User Matches

This document provides a technical walkthrough of how "Matches" are formed and verified in the Tavern Swiper ecosystem. Use this as a reference when modifying the Discovery service.

## 🚀 The Match Lifecycle

Matches are a distributed event involving multiple microservices. No single service owns the entire state; they interact via REST APIs as follows:

1.  **Identity Creation (`Profiles` Service)**:
    *   A user must forge an identity before entering the Tavern.
    *   **Logic**: `POST /profiles/` saves the profile and attributes to the `profiles` Firestore database.
    *   **Agent Tip**: The frontend must set `activeProfileId` immediately after creation to ensure the Discovery feed loads the correct context.

2.  **Discovery Feed (`Discovery` Service)**:
    *   The Tavern feed is generated by filtering for all profiles *except* those belonging to the current `user_id` and those already swiped by the `activeProfileId`.
    *   **Logic**: `GET /discovery/feed/{profile_id}`.
    *   **Dependency**: Discovery queries the `Profiles` service to get candidate details.

3.  **The Swipe (`Discovery` Service)**:
    *   When a user likes a hero, a swipe record is created.
    *   **Logic**: `POST /discovery/swipe` with `swiper_profile_id`, `swiped_profile_id`, and `direction='right'`.
    *   **Match Check**: The Discovery service automatically checks if a reciprocal RIGHT swipe exists from the target profile to the swiper. If it does, a **Match** record is created.

4.  **Match Retrieval**:
    *   **Logic**: `GET /discovery/matches/{profile_id}` returns all mutual matches for that specific identity.

## 🧪 Testing and Verification

Because the system is "Zero-Trust," we never assume the UI "knows" a match happened. We always verify the state directly via the backend.

### **Testing Strategy**
*   **Jest Unit Tests**: Frontend hooks and components are tested in isolation using mocked API responses via `@testing-library/react-native`.
*   **UI Anchors**: The `index.tsx` contains `swipe-left-button` and `swipe-right-button` `testIDs` for reliable interaction testing.
*   **Integration Tests (Pytest)**: Backend integration tests call the REST APIs directly to confirm match records exist after mutual swipes.

### **Common Gotchas**
*   **Authorization**: Every API call requires a Bearer Token. In tests, mock the token or capture it from Firebase Auth during setup.
*   **Active Profile**: The Discovery feed requires an `activeProfileId` — tests must set this before querying the feed.
